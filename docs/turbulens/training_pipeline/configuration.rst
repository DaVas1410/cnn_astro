Configuration
=============

An experiment is defined by one YAML file. The canonical scientific
configuration is ``configs/config_base.yaml``. Experiment files such as
``configs/config_multitask.yaml`` or ``configs/config_single_sigma.yaml``
start with ``extends: config_base.yaml`` and override only what differs.
The four single-target files are generated by
``generate_single_target_configs.py``.

Experiment versions
-------------------

``experiment.version`` (for example ``local_v2``) names the result
directory ``<output_root>/<multitask|single_<target>>/<version>/``. The
first run of a version saves the resolved configuration and its SHA-256
hash; later runs must hash identically. To change any scientific
setting, change the version (for example to ``local_v3``) instead of
editing the configuration in place. ``allow_config_change: true``
overrides the check and is meant for non-scientific fixes only.

Stage selection is a command-line choice (``--to-stage``,
``--from-stage``, ``--stages``), not a configuration key, so running part
of an experiment never creates a second configuration with a different
hash.

Sections
--------

``experiment``
   ``project_root`` and ``output_root`` (paths resolved relative to the
   YAML file and the project root), ``version``, ``allow_config_change``.

``data``
   ``small_root`` (screening data) and ``large_root`` (candidate and
   final data), ``split_directories`` (names of the train, validation
   and test folders), ``require_square_for_augmentation``,
   ``enforce_disjoint_files``, and ``normalization``: the percentiles
   (0.5 and 99.5), the sample caps (``max_images``, ``max_pixels``) and the
   seed for the training-only pixel normalization.

``model``
   The backbones, input-channel modes and pretraining options searched;
   ``pretrained_weights`` (the exact torchvision ImageNet weights per
   backbone); ``preserve_resolution`` (remove the max-pool);
   ``input_standardization`` (``imagenet`` or ``none``);
   ``shared_dimensions`` (fixed at ``[512, 256]``);
   ``head_hidden_dimension``; ``dropout_policy``, the mapping from the
   searched base dropout to per-layer rates (:ref:`architecture`).

``search``
   ``space`` (the factorial grid), ``seeds`` and
   ``repetitions_per_configuration`` for screening, and ``selection``:
   ``metric`` (``mse``, ``rmse``, ``r2`` or the combined ``mse_r2``),
   ``target`` (``overall`` or one target), the metric space, ``group_by``
   and ``top_per_group`` (candidates kept per group; ``top_k`` only sizes
   the report table), and ``require_all`` (wait for every run before
   selecting).

``candidate_training``
   Seeds and repetitions for large-data confirmation, and the final
   selection settings. With ``group_by: null``, ``top_per_group`` is the
   number of final configurations selected (one).

``ensemble``
   ``members`` and their ``seeds``, the shared ``normalization_seed``,
   ``interval_levels`` for coverage summaries, and
   ``bootstrap_repetitions``.

``training``
   ``epochs``, ``gradient_clip_norm`` (0 disables clipping), ``optimizer``
   (AdamW settings), ``scheduler`` (ReduceLROnPlateau settings),
   ``early_stopping`` (monitors validation loss), ``augmentation``,
   ``amp``, ``deterministic``, ``cudnn_benchmark`` (disabled automatically
   in deterministic mode), and data-loader performance settings
   (``num_workers``, ``prefetch_factor``, ``pin_memory``,
   ``persistent_workers``), which are not scientific factors.

``evaluation``
   Which splits each stage evaluates. Test evaluation is off for grid
   and candidate stages and on only for final members.

``runtime``
   ``gpus``, ``max_parallel_jobs``, ``device`` (``cuda``, ``cpu`` or
   ``auto``), ``python_executable`` (``current`` for the interpreter that
   started the pipeline), ``gpu_wait`` (wait for GPUs to be free, without
   changing any training setting), and environment variables for child
   processes.

``checkpointing`` and ``storage``
   Checkpoint frequency, resume and verification; how much each kind of
   run keeps on disk (:doc:`outputs`).

``interpretability``
   Embedding layer, sample caps, and PCA, CCA and UMAP settings. Its batch
   sizes are analysis controls, unrelated to the training batch size.

Every resolved key and its value is written to each run's
``configuration.json``, so a trained member always carries the full
configuration that produced it.
